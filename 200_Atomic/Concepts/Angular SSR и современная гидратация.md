# Angular SSR и современная гидратация

## Core Idea
Angular SSR генерирует готовый HTML-каркас на сервере для мгновенного отображения, а гидратация оживляет его в браузере, подключая логику и обработчики событий без перерисовки DOM.

## Why It Matters
Это решение устраняет проблемы «белого экрана» и SEO при загрузке SPA-приложений, обеспечивая быструю загрузку первой страницы (FCP/LCP) и отзывчивый интерфейс без мерцания.

## Key Points

- **От разрушения к бесшовности:** Старый Angular полностью уничтожал серверный HTML и рендерил его заново; Angular 16+ переиспользует существующие DOM-узлы.
  
- **Невидимая связка:** Сервер отдаёт статическую «сухую» форму (HTML), а клиентский JavaScript «увлажняет» её (Hydration), навешивая listeners и восстанавливая state.
  
- **TBT и Hydration Mismatch:** Главные риски гидратации — блокировка основного потока из-за тяжелого JS и ошибки расхождения DOM-дерева между сервером и клиентом.
  
- **Эволюция в хирургическую гидратацию:** Современный веб уходит от монолитного оживления страницы к частичной/отложенной гидратации (`@defer` в Angular 17+), островам (Astro) и возобновляемости (Qwik).

## Examples

### Example 1
Покупка мебели в ИКЕА.  
Обычный CSR — тебе привозят пустую коробку и инструкцию (собираешь сам).  
Старый SSR — тебе привозят собранный шкаф, но мастер полностью разбирает его у тебя на глазах и собирает заново.  
SSR + Modern Hydration — мастер приходит и просто подкручивает петли и замки на готовом шкафу.

### Example 2
Заварка сухой лапши.  
HTML от сервера — это сухая лапша (уже имеет форму и структуру, но не интерактивна).  
JavaScript — это кипяток.  
Процесс заливки водой и оживления продукта — это гидратация.

## How to Apply

1. Включить `provideClientHydration()` в `app.config.ts` (или `app.module.ts`).
2. Писать строго валидный HTML (избегать неверной вложенности тегов вроде `<p><div>...</div></p>`).
3. Изолировать обращения к browser-only API (`window`, `document`, `localStorage`) через `isPlatformBrowser` или хук `afterNextRender`.
4. Использовать `TransferState` для синхронизации данных API между сервером и клиентом без повторных HTTP-запросов.
5. Использовать `@defer (on viewport)` для отложенной гидратации тяжёлых компонентов ниже первого экрана.
