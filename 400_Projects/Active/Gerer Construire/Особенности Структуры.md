## Content
[Main information, thoughts, or description]
1. **Nx Monorepo**: Enables:
    
    - Shared code across feature modules
    - Workspace-wide dependency tracking
    - Isolated build/test boundaries per library
    - Scalable organization for teams (each module can be owned)
2. **DDD Layering**: Each module separates concerns:
    
    - **Domain**: Business logic, entities, interfaces (pure TS, no Angular)
    - **Application**: Use cases, orchestration (pure TS)
    - **Infrastructure**: HTTP calls, stores, mappers (Angular-aware)
    - **Presentation**: Components (pure UI rendering)
    
    This means: **You can test domain logic without Angular**. That's powerful for junior devs to understand.
    
3. **Design System as a Separate Concern**: Components, icons, and form abstractions are isolated from feature logic. This prevents:
    
    - Tight coupling between UI components and business modules
    - Duplicating component code across modules
    - Making design changes cascade across features
4. **Signal-Based State Management**: Using `@ngrx/signals` and Angular's native [signal()](vscode-file://vscode-app/c:/Users/momom/AppData/Local/Programs/Microsoft%20VS%20Code/072586267e/resources/app/out/vs/code/electron-browser/workbench/workbench.html) instead of RxJS-heavy patterns:
    
    - More performant (fine-grained reactivity)
    - Easier to understand for junior devs (imperative vs. stream-based)
    - Less boilerplate than NgRx **store**
